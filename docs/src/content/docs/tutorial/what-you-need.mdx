New to Discord bots? Start here. This tutorial takes you from an empty folder to a
**working, deployed bot** - explaining every step. No prior bot experience needed.

## What a Discord bot actually is

A bot is just **a program on your computer that logs into Discord**, like a user
would. Discord sends it events ("someone typed `/ping`"), your program decides what
to do, and replies.

<CardGrid>
  <Card title="Your code" icon="laptop">
    A Node.js program using `djs-bot`. It runs on your machine (or a server).
  </Card>
  <Card title="The application" icon="discord">
    An entry in Discord's Developer Portal. It holds your bot's identity and its **token** (its password).
  </Card>
  <Card title="The connection" icon="random">
    Your program uses the token to log in. Discord then streams events to it in real time.
  </Card>
</CardGrid>

<Aside type="note" title="You don't need a server yet">
While developing, your bot runs on your own computer. It appears **online** in
Discord only while your program is running. Hosting comes later, in
[step 7](/djs-bot/tutorial/going-live/).
</Aside>

## Install the tools

<Steps>

1. **Node.js 22 or newer**

   `djs-bot` needs Node 22+ (it uses the built-in `node:sqlite`). Download the
   **LTS** build from [nodejs.org](https://nodejs.org).

   Check it worked:

   ```bash
   node --version
   # v22.x.x or higher
   ```

   <Aside type="caution">
   If you see `v20` or lower, `djs-bot` will not start. Install a newer Node.
   </Aside>

2. **A code editor**

   [VS Code](https://code.visualstudio.com) is the usual choice and free. It
   understands TypeScript out of the box, which means it will show you your bot's
   errors *before* you run it.

3. **A Discord account and a server you can manage**

   You need a server where you have the **Manage Server** permission, to invite
   your bot. Making a personal one takes 10 seconds: in Discord, click the **+**
   in the server list → *Create My Own*.

</Steps>

## TypeScript or JavaScript?

`djs-bot` works with both. This tutorial uses **TypeScript**, because the whole
point of the framework is that your editor catches mistakes for you (a wrong option
name, a missing argument) instead of your bot crashing at 2am.

<Tabs>
  <TabItem label="TypeScript (recommended)">
    You write `.ts` files. Your editor autocompletes every option and flags typos.
    You do **not** need to compile anything during development - `djs-bot dev` runs
    TypeScript directly.
  </TabItem>
  <TabItem label="JavaScript">
    Everything in this tutorial works in `.js` too - drop the type annotations. You
    still get autocomplete, because the package ships full type definitions.
  </TabItem>
</Tabs>
