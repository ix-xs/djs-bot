`/server` and `/user` appeared without being "plugged in" anywhere. Here is
how, and what it changes for organizing your project.

## The problem it solves

In a discord.js bot written by hand, adding a command means touching several
places: the file, a list that gathers them, the code that calls the right
one, the script that sends them to Discord. Forget one, and the command does
not appear. With djs-bot, only **the file** is left.

## The file name is how it is found

At startup, the bot goes through `features` and its subfolders, and loads
every file that ends with one of these suffixes:

| Suffix | What it contains |
| --- | --- |
| `.command.ts` | a slash command |
| `.user.ts` / `.message.ts` | a right-click action on a member / a message |
| `.button.ts` | a button |
| `.select.ts` | a select menu |
| `.modal.ts` | a form |
| `.event.ts` | an event listener |
| `.trigger.ts` | an automatic reply to a message |
| `.job.ts` | a scheduled task |
| `.service.ts` | a shared service |
| `.plugin.ts` / `.feature.ts` | a plugin / a grouped feature |

`.js`, `.mjs` and `.cjs` work too. Everything else is ignored (`utils.ts`,
`ping.command.test.ts`, `.d.ts` files): keep your helper code next to it
without worry.

## The `define` function says what it is

The suffix is used to **find** the file. The `define...` function you used is
what says what it contains, and a file can export several:

```ts title="src/features/tickets/ticket.command.ts"
import { defineButton, defineCommand, ui } from "@ix-xs/djs-bot";

// A button, declared in the same file as the command: it is loaded too.
export const close = defineButton({
  id: "ticket-close",
  label: "Close",
  run: (ctx) => ctx.update({ content: "Ticket closed.", components: [] }),
});

export default defineCommand({
  name: "ticket",
  description: "Open a support ticket",
  run: (ctx) => ctx.reply({ content: "Ticket opened.", components: [ui.row(close.build())] }),
});
```

<DiscordDemo
  steps={[
    { do: "command", name: "ticket", description: "Open a support ticket" },
    { do: "reply", text: "Ticket opened.", buttons: [{ label: "Close" }] },
    { do: "click", button: "Close" },
    { do: "reply", text: "Ticket closed.", edit: true },

/>

Importing a file triggers nothing: it only **describes**. That is what lets
the tools read the bot without connecting it.

## Organizing a project that grows

The location does not matter to the bot: organize for humans, **one folder
per feature**.

<FileTree>
- src/
  - index.ts
  - features/
    - ping/
      - ping.command.ts
    - info/
      - server.command.ts
      - user.command.ts
    - tickets/
      - ticket.command.ts      opens a ticket
      - close.button.ts        closes it
      - tickets.service.ts     stores them
      - format.ts              helper code, ignored
    - welcome/
      - welcome.event.ts
</FileTree>

Where is the tickets code? In `tickets/`. Remove the feature? Delete the
folder.
