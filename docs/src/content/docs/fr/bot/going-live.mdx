Le bot ne vit que tant que `djs-bot dev` tourne. Pour qu'il réponde à toute
heure, il doit tourner sur une machine toujours allumée : un serveur.

## Le mode production

Sur le serveur, on lance `start` au lieu de `dev` :

<TerminalDemo
  command="NODE_ENV=production npx djs-bot start"
  lines={[
    { text: '{"level":"info","time":"2026-11-08T14:40:12.031Z","msg":"Ready","user":"my-bot#1234","guilds":1,"version":"1.4.1"}', delay: 900 },
  ]}
/>

| | `dev` | `start` en production |
| --- | --- | --- |
| Redémarre à chaque modification | oui | non |
| Enregistre les commandes au démarrage | oui, sur votre serveur de test | non, c'est vous qui lancez `deploy` |
| Journaux | en couleurs, pour vous | en JSON, pour les outils du serveur |

## Où l'héberger

Sur toute machine qui fait tourner Node 22.23.4+, 24.22.1+ ou 26.12.1+ :

<Tabs>
  <TabItem label="Un serveur Linux (VPS)">
    Copiez le projet, lancez `npm ci`, puis confiez le bot à systemd, qui le
    démarre avec la machine et le relance s'il s'arrête :

    ```ini title="/etc/systemd/system/mybot.service"
    [Unit]
    Description=My Discord bot
    After=network.target

    [Service]
    WorkingDirectory=/srv/my-bot
    ExecStart=/usr/bin/npx djs-bot start
    Environment=NODE_ENV=production
    EnvironmentFile=/srv/my-bot/.env
    Restart=always
    RestartSec=5

    [Install]
    WantedBy=multi-user.target
    ```

    ```bash
    sudo systemctl enable --now mybot
    sudo journalctl -u mybot -f
    ```

    La seconde commande affiche les journaux en direct.
  </TabItem>
  <TabItem label="Docker">
    ```dockerfile title="Dockerfile"
    FROM node:26-alpine
    WORKDIR /app
    COPY package*.json ./
    RUN npm ci
    COPY . .
    ENV NODE_ENV=production
    CMD ["npx", "djs-bot", "start"]
    ```

    Donnez le token au lancement (`docker run -e DISCORD_TOKEN=...`), jamais
    dans l'image : une image se partage.
  </TabItem>
  <TabItem label="Une plateforme (Railway, Fly...)">
    Commande de démarrage : `npx djs-bot start`. Variables :
    `DISCORD_TOKEN`, `DISCORD_CLIENT_ID`, `NODE_ENV=production`. Publiez les
    commandes une fois depuis votre ordinateur avec `npx djs-bot deploy`.
  </TabItem>
</Tabs>

Comparatif complet : [Héberger en production](/recipes/hosting/).

## Les secrets en production

`.env` reste sur votre ordinateur. Sur le serveur, le token vient de
l'hébergement : `EnvironmentFile` de systemd, `-e` de Docker, ou l'écran des
variables de la plateforme. `env("DISCORD_TOKEN")` le lit pareil.

<Aside type="danger">
Token visible là où il ne devrait pas ? **Reset Token** dans le Developer
Portal, puis mettez le nouveau sur le serveur.
</Aside>

## Publier la première version

<Steps>

1. `npx djs-bot deploy` depuis votre ordinateur.
2. `npx djs-bot clear --guild <id du serveur de test>` pour retirer les doubles.
3. Sur le serveur : `NODE_ENV=production npx djs-bot start`.
4. Dans Discord : le bot est en ligne, `/ping` répond.

</Steps>

Ensuite, à chaque version : mettez le code à jour sur le serveur, redémarrez
le bot, et relancez `deploy` seulement si une commande a changé.
