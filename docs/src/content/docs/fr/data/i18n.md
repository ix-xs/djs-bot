Trois choses différentes s'appellent « traduction » sur un bot Discord, et
chacune a son propre mécanisme :

| Quoi | Où cela s'affiche | Comment |
| --- | --- | --- |
| Les messages que votre bot envoie | Réponses, embeds, boutons | `ctx.t()`, configuré avec `i18n` (cette page) |
| Les noms et descriptions des commandes | Le sélecteur de commandes | `nameLocalizations` sur la définition ([plus bas](#command-names-and-descriptions)) |
| Les messages que le framework envoie | Refus des gardes, l'erreur générique | `messages`, voir [Formulations et thème](/basics/wording-and-theme/) |

## Une première traduction

Déclarez un arbre de messages par langue dans `defineBot` :

```ts title="src/index.ts"
import { defineBot, env } from "@ix-xs/djs-bot";

export default defineBot({
  token: env("DISCORD_TOKEN"),
  features: "./features",
  i18n: {
    defaultLocale: "en",
    resources: {
      en: {
        daily: { claimed: "You claimed {amount} coins." },
        items: { one: "{count} item", other: "{count} items" },
      },
      fr: {
        daily: { claimed: "Vous avez reçu {amount} pièces." },
        items: { one: "{count} objet", other: "{count} objets" },
      },
    },
  },
});
```

Appelez ensuite `ctx.t` dans n'importe quel gestionnaire d'interaction. Les
clés imbriquées s'écrivent avec des points.

```ts title="features/economy/daily.command.ts"
import { defineCommand } from "@ix-xs/djs-bot";

export default defineCommand({
  name: "daily",
  description: "Claim your daily coins",
  run: async (ctx) => {
    // Un utilisateur français lit "Vous avez reçu 100 pièces.", les autres la chaîne anglaise.
    return ctx.reply.success(ctx.t("daily.claimed", { amount: 100 }));
  },
});
```

`ctx.t` traduit pour `ctx.locale`, la langue du client Discord de l'utilisateur.
Ce n'est pas la langue du serveur : deux personnes du même serveur peuvent
obtenir des langues différentes de la même commande.

Sans `i18n` dans la configuration, `ctx.t(key)` renvoie la clé. Les
gestionnaires écrits avec `ctx.t` continuent donc de fonctionner, et ajouter des
traductions plus tard ne casse rien.

## Variables et pluriels

Les marqueurs `{name}` sont remplacés à partir du second argument. Les chemins
avec des points atteignent l'intérieur des objets.

```ts
// en: { greet: "Hello {name}", owner: "Owned by {owner.name}" }
ctx.t("greet", { name: ctx.user.username });   // "Hello Ada"
ctx.t("owner", { owner: { name: "Ada" } });    // "Owned by Ada"
ctx.t("greet", {});                            // "Hello "
ctx.t("greet");                                // "Hello {name}"
```

Une variable absente de l'objet devient une chaîne vide. Quand aucun objet
n'est passé du tout, le texte est renvoyé tel qu'il est écrit, marqueurs
compris.

Pour un pluriel, donnez à la clé une paire `{ one, other }` et passez `count` :

```ts
// en: { items: { one: "{count} item", other: "{count} items" } }
ctx.t("items", { count: 1 });   // "1 item"
ctx.t("items", { count: 5 });   // "5 items"
ctx.t("items", { count: 0 });   // "0 items"
```

La règle est la même pour toutes les langues : `one` quand `count` vaut `1`,
`other` pour tout le reste, y compris `0` et l'absence de `count`. Les langues
qui ont plus de deux formes de pluriel demandent des clés séparées, entre
lesquelles vous choisissez vous-même.

:::caution[Noms de clés réservés]
Tout objet qui contient à la fois une clé `one` et une clé `other` est lu comme
une paire de pluriel. Ne donnez pas ces deux noms à un groupe de messages
ordinaires.
:::

## Repli de langue

Discord envoie des langues comme `"fr"`, `"en-US"`, `"en-GB"` ou `"pt-BR"`.
Pour chaque clé, le traducteur essaie dans l'ordre :

1. la langue exacte, par exemple `"en-US"`
2. sa langue de base, `"en"`
3. `fallbackLocale`, quand il est défini
4. `defaultLocale`
5. la clé elle-même, renvoyée telle quelle

L'étape 2 explique pourquoi des ressources indexées par `en` couvrent à la fois
`en-US` et `en-GB`. La chaîne s'applique clé par clé, donc une langue peut être
traduite partiellement : les clés manquantes viennent de l'étape suivante.

La dernière étape signifie qu'une traduction manquante se dégrade en une clé
visible comme `ticket.opened`, pas en plantage ni en message vide. C'est
évident en test et sans danger en production. Une clé qui pointe vers un groupe
de messages, et non vers un message, compte aussi comme manquante.

## Fichiers de traduction

`resources` est un simple objet, chargez-le donc comme vous voulez. Un fichier
JSON par langue garde les traducteurs hors de votre code :

```ts title="src/locales/index.ts"
import en from "./en.json" with { type: "json" };
import fr from "./fr.json" with { type: "json" };

export const resources = { en, fr };
```

```ts title="src/index.ts"
import { defineBot, env } from "@ix-xs/djs-bot";
import { resources } from "./locales/index.js";

export default defineBot({
  token: env("DISCORD_TOKEN"),
  features: "./features",
  i18n: { defaultLocale: "en", resources },
});
```

## Hors des gestionnaires d'interaction

`ctx.t` existe là où il y a un utilisateur et donc une langue : commandes,
menus contextuels, boutons, menus de sélection, modales et gestionnaires
d'autocomplétion. Les événements, les déclencheurs et les tâches planifiées
n'ont pas de `ctx.t`. Dans ces cas, et partout ailleurs (un service, une
annonce planifiée), construisez un traducteur avec `createI18n` et passez la
langue vous-même :

```ts title="src/i18n.ts"
import { createI18n } from "@ix-xs/djs-bot";
import { resources } from "./locales/index.js";

export const i18n = createI18n({ defaultLocale: "en", resources });

i18n.t("fr", "greet", { name: "Léa" });        // "Bonjour Léa"
i18n.t(undefined, "greet", { name: "Léa" });   // pas de langue : la langue par défaut, "Hello Léa"
i18n.locales();                                // ["en", "fr"]
i18n.defaultLocale;                            // "en"
```

Passez le même objet `resources` à `defineBot` et à `createI18n` pour que les
deux lisent un seul jeu de messages.

## Noms et descriptions des commandes

Ce que l'utilisateur voit dans le sélecteur de commandes relève d'un autre
mécanisme : Discord le traduit lui-même, à partir des `nameLocalizations` et
`descriptionLocalizations` déclarés sur la commande. Il est indépendant de
`ctx.t` et fonctionne sans `i18n`. Il est décrit dans
[Noms localisés](/commands/slash-commands/#localized-names).

Un bot entièrement traduit utilise les deux : des noms localisés pour qu'un
utilisateur français tape `/aide`, et `ctx.t()` pour que la réponse soit aussi
en français.

## Référence

Chaque option, propriété et type, avec ce qu'il accepte et renvoie, est dans la référence de l'API :

- `I18nOptions` : Options de `createI18n`.
- `defineBot()` : Crée un `Bot`.
- `createI18n()` : Crée un traducteur.
- `Messages` : Un arbre (éventuellement imbriqué) de chaînes de traduction.
- `I18n` : Un traducteur produit par `createI18n`.
