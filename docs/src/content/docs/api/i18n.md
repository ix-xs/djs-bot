There are **two** different things people call translation on Discord, and the
framework handles both separately:

| What | Where it shows | How |
| --- | --- | --- |
| Command **names & descriptions** | The command picker | `nameLocalizations` on the definition |
| The messages your bot **sends** | Replies, embeds, buttons | `ctx.t()`, configured here |

## Setup

```ts title="src/index.ts"
export default defineBot({
  i18n: {
    defaultLocale: "en",
    fallbackLocale: "en",
    resources: {
      en: {
        greet: "Hello {name}!",
        items: { one: "{count} item", other: "{count} items" },
        ticket: { opened: "Ticket #{id} opened", closed: "Ticket #{id} closed" },
      },
      fr: {
        greet: "Bonjour {name} !",
        items: { one: "{count} objet", other: "{count} objets" },
        ticket: { opened: "Ticket #{id} ouvert", closed: "Ticket #{id} fermé" },
      },
    },
  },
});
```

### `I18nOptions`

| Field | Type | Default | Description |
| --- | --- | --- | --- |
| `resources` | `Record<string, Messages>` | - | **Required.** Message trees, keyed by locale. |
| `defaultLocale` | `string` | `"en"` | Used when the user locale has no entry. |
| `fallbackLocale` | `string` | - | Tried *before* the default. |

`Messages` is a nested tree whose leaves are either a `string` or a plural pair
`{ one, other }`.

## `ctx.t()`

```ts
ctx.t(key: string, vars?: Record<string, unknown>): string
```

Translates for `ctx.locale` - the locale of the user Discord client, so two
people in the same server can get different languages from the same command:

```ts
run: (ctx) => ctx.reply.success(ctx.t("ticket.opened", { id: 42 })),
```

Nested keys use dots: `"ticket.opened"`.

If i18n is not configured, `ctx.t()` simply returns the key - so adding
translations later never breaks anything.

## Interpolation

`{var}` placeholders are replaced from `vars`. A missing variable becomes an
empty string rather than the literal `{name}`:

```ts
ctx.t("greet", { name: ctx.user.username });   // "Bonjour Léa !"
```

## Pluralisation

Give a key a `{ one, other }` pair and pass `count`:

```ts
resources: {
  en: { items: { one: "{count} item", other: "{count} items" } },
}

ctx.t("items", { count: 1 });   // "1 item"
ctx.t("items", { count: 5 });   // "5 items"
ctx.t("items", { count: 0 });   // "0 items"
```

## Locale resolution

For each lookup the framework tries, in order:

1. the exact locale - `"en-US"`
2. its base language - `"en"`
3. `fallbackLocale`
4. `defaultLocale`
5. the key itself, returned unchanged

That last step means a missing translation degrades to a visible key such as
`ticket.opened` rather than a crash or an empty message - obvious in testing,
harmless in production.

## Using the translator directly

`createI18n` is a standalone function; use it outside handlers (in a service, a
job, a scheduled announcement):

```ts
import { createI18n } from "@ix-xs/djs-bot";

const i18n = createI18n({ defaultLocale: "en", resources });

i18n.t("fr", "greet", { name: "Léa" });   // "Bonjour Léa !"
i18n.locales();                            // ["en", "fr"]
i18n.defaultLocale;                        // "en"
```

| Member | Description |
| --- | --- |
| `t(locale, key, vars?)` | Translate, with the fallback chain above. |
| `locales()` | Every locale that has resources. |
| `defaultLocale` | The configured default. |

## Splitting translations into files

`resources` is a plain object, so load it however you like:

```ts title="src/locales/index.ts"
import en from "./en.json" with { type: "json" };
import fr from "./fr.json" with { type: "json" };

export const resources = { en, fr };
```

```ts
import { resources } from "./locales/index.js";
export default defineBot({ i18n: { defaultLocale: "en", resources } });
```

## Localising command names

Independent of `ctx.t`, and handled by Discord itself:

```ts
export default defineCommand({
  name: "help",
  description: "Show help",
  nameLocalizations: { fr: "aide", "es-ES": "ayuda" },
  descriptionLocalizations: { fr: "Afficher l'aide", "es-ES": "Mostrar ayuda" },
  options: {
    topic: s.string({
      description: "Topic",
      nameLocalizations: { fr: "sujet" },
      descriptionLocalizations: { fr: "Le sujet" },
    }),
  },
  run: (ctx) => ctx.reply(ctx.t("help.body")),
});
```

A French user then types `/aide sujet:...` and reads a French answer.

:::caution
Localized names must obey the same rules as the base name: lowercase, 1-32
characters, no spaces. Locale codes are Discord ones (`fr`, `es-ES`, `pt-BR`, …).
:::
