<section class="at-section">
  <header data-reveal><span>02</span><h2>What you stop writing</h2></header>
  <ul class="at-points">
    <li data-reveal><h3>Casts and null checks</h3><p>Options, customId params, modal fields, services and config are typed from their declaration. <code>required: true</code> makes the value non-optional.</p></li>
    <li data-reveal><h3>Registration and intents</h3><p>Commands are diffed and deployed for you, and the gateway intents are derived from the events you listen to.</p></li>
    <li data-reveal><h3>"The application did not respond"</h3><p>Turn on automatic deferral once. A slow handler is acknowledged for you, and it never collides with your own reply.</p></li>
    <li data-reveal><h3>String parsing in buttons</h3><p>A button carries typed data in its customId. The click comes back to your handler decoded, with no <code>split("_")</code>.</p></li>
    <li data-reveal><h3>The production checklist</h3><p>Error boundary, graceful shutdown, structured logs, sharding, health checks, metrics, rate limits and a store with atomic counters are built in.</p></li>
    <li data-reveal><h3>A test server for every change</h3><p>Handlers are plain functions. The harness runs a command, a button or a form and captures the reply, with no token and no network.</p></li>
  </ul>
</section>
