The bot exists on Discord. Now it needs a program on your computer: Node.js
to run it, a folder, and a few packages.

## Install Node.js

Node.js runs JavaScript outside the browser: it is what will run the bot.
Install the **LTS** version from [nodejs.org](https://nodejs.org), then
check:

<TerminalDemo
  command="node --version"
  lines={[{ text: "v26.13.0" }]}
/>

| Node line | Minimum version |
| --- | --- |
| Node 22 | 22.23.4 |
| Node 24 | 24.22.1 |
| Node 26 | 26.12.1 |

Node 23 and 25 are not supported. Older versions have a flaw in their
`fetch()` that lets someone stop the program remotely.

Get an editor too: [VS Code](https://code.visualstudio.com) is free and
understands TypeScript on its own.

`package.json` describes the project and the list of its packages.

## Install the packages

```bash
npm install @ix-xs/djs-bot discord.js
npm install -D tsx typescript @types/node
```

| Package | Why |
| --- | --- |
| `@ix-xs/djs-bot` | the framework |
| `discord.js` | the library that talks to Discord |
| `tsx` | runs your TypeScript files with no build step |
| `typescript` | checks your code, makes autocompletion work |
| `@types/node` | describes Node.js to TypeScript |

The second line (`-D`) installs tools to **write** the bot, not to run it.

<FileTree>
- my-bot/
  - .env                    your secrets (the token), never published
  - .env.example            the same file, empty, can be published
  - .gitignore              what git ignores, including `.env`
  - package.json            the project and its scripts
  - tsconfig.json           TypeScript's settings
  - src/
    - index.ts              the bot itself
    - types.d.ts            your services, later
    - features/             one feature per folder
      - ping/
        - ping.command.ts   the `/ping` command
</FileTree>

<Aside type="note" title="What about JavaScript?">
Rename the files to `.js` and remove the type annotations: the rest is the
same, and autocompletion stays (the package ships its own types). `require`
works as well as `import`.
</Aside>

`init` does not overwrite any existing file. It adds scripts to
`package.json` (`npm run dev`...) and switches it to ES modules.

The project is ready, but `.env` is still empty: that is the next page.
